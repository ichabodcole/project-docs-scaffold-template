# The v2.10 migration reconciles, and its verify phase is meant to go red

`v2.9-to-v2.10` refreshes `scripts/pdocs/` and `docs/SCHEMA.md` and reconciles
every seeded template through the manifest's verdicts — update, install, or keep
with a named reason. It is the first migration to use that API on a real tree
and the first written under `migration-authoring` by someone other than the
skill's own author.

**Key files:**
`plugins/project-docs/skills/update-project-docs/migrations/scripts/migrate-v2.9-to-v2.10.ts`,

## What was non-obvious

- **A refresh that makes the lint go red is still correct.** The newer lint sees
  a real page the older one hid. Rolling back would reinstall the bug, so the
  script stops after the refresh and before the version markers, with the count
  of problems that are new against a baseline taken under the old CLI.
- **The precondition is a content marker in the installed CLI**, not a version
  number: a tree is behind while its `rules.ts` lacks `isSeeded`. A tree with no
  CLI at all belongs to v2.6-to-v2.7.
- **A guard that cannot be made to fail is removed, not annotated.** Three were:
  two post-copy marker checks that phase 2 had already verified on the source,
  and a defensive write refusal.
- **The skill is converging, not converged.** Five gaps from the first author,
  seven from the second. Every one was found by building, none by reading.
