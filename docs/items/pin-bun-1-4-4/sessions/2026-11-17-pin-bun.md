# Pin Bun 1.4.4 in CI — 2026-11-17

Part of
[Check fixes and board research](../../../cycles/2026-11-check-fixes-and-board-research.md).

## Context

The CI hang research (`item/ci-migration-test-git-hang-cause`) traced hung
`docs-check` runs to Bun 1.4.0: a garbage collection that runs while `spawnSync`
waits can make it miss the child's exit. Bun 1.4.4 carries the fix. The
development machine moved to 1.4.4 the same day, so the pin could follow.

## What Happened

`.github/workflows/docs-check.yml` was the only place the repository pins Bun.
Its `bun-version` went from 1.4.0 to 1.4.4, and `npm run check` passed on 1.4.4
(1587 tests). Nothing else moved: `@types/bun` stays as locked, and the adopter
CI snippet in the v2.6 to v2.7 migration guide sets no version.

Spellbook reported three behaviour changes in 1.4.4 on the `kit-parity` channel:
`Bun.Image` decodes a truncated JPEG, a WebSocket's `onopen` resolves before the
first frame, and `fetch` gives a 204 a null body. `scripts/` and `plugins/` use
none of those APIs.
