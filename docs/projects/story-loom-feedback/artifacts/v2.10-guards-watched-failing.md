# v2.10: guards watched failing

The `v2.9-to-v2.10` script — the second branch of
[Story-loom feedback, round 1](../../../cycles/2026-09-story-loom-feedback.md),
specified by the
[backlog item](../../../backlog/2026-09-14-v2.9-to-v2.10-refresh-the-owned-files.md).
Every `fail(` site, every line the end-of-run invariant can produce, `main`'s
three exits and the test seam's refusal, each with the test that covers it and
the observation.

**Method.** The same runner shape as
[the v2.6 record](../../migration-shape/artifacts/phase-3-guards-watched-failing.md):
`watch-guards-fail.ts` (scratchpad) took the intact file, and for each guard in
turn replaced that one guard's condition with `false` (or its `fail(` with
`void(`) **in place**, ran the covering test(s) with
`bun test <file> -t <name>`, recorded the red count and the names of the tests
that went red, restored the intact file byte-for-byte, ran the same tests again
and recorded green. The runner refuses a guard whose text it cannot find or that
occurs twice, so a renamed guard cannot be silently skipped. 39 guards, 0
problems; `grep -c 'if (false)'` on the restored file is 0. Line numbers are of
the file as run.

**Three guards were removed before this pass rather than annotated.** The
refresh phase first checked the `isSeeded` marker on the installed `rules.ts`
and the exact-shape row on the installed `SCHEMA.md` right after each copy — the
shape the authoring skill asks of a single-path copy. Phase 2 verifies both
markers on the source before anything is written, so a copy that succeeds cannot
lack them and neither check could be watched failing; they are gone, and the
end-of-run invariant (I1, I2) reads the markers back from the installed files
instead, which the phase-3 wiring witness turns red. That is the resolution the
v2.6 record reached for its G14, now written into the skill. A defensive
`refusing to write` guard in the reconcile loop went the same way: only the two
verdicts that permit writing reach the loop, so it could not fire.

**The designed stop (V1).** The verify phase's stop is not a defect path: the
refreshed lint judges pages the older one hid, the refresh stays, and the
markers do not move. Five tests turn red when it is neutered, among them the
story-loom fixture — a real `docs/specifications/templates.md` with no
frontmatter, clean under the 8.0.0 lint (the fixture asserts it) and three
problems under the refreshed one — where the neutered script moved both markers
to `9.9.9` on a red tree.

**After the finalize review**, one guard was added and one message rewritten,
and the whole list re-observed. **G0**: a `.project-docs.json` that starts with
a UTF-8 byte-order mark is named as such rather than as the token JSON refuses.
**V1**'s baseline sentence was a count difference (`refreshed − baseline`), and
the reproduction — the old lint judging a recorded non-template page the new
lint skips, beside the page only the new lint judges — made it say "2 of these
are new" when all three were new and the one was gone; it is now a set
difference on the problem lines, reported as new / no longer reported /
unchanged. That test was written first and watched red against the count
(`Expected to contain: … 3 new to the refreshed lint, 1 no longer reported, 0 unchanged`),
then green. The manifest writer also drops a key `within()` rejects and names
it, which adds a `·` line rather than a guard.

Test names are the `describe > test` titles in `migrate-v2.9-to-v2.10.test.ts`;
the suite and this note can be read against each other.
