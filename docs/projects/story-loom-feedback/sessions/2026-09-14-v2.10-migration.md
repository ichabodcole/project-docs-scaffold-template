## What the migration does that no earlier one did

- **It reconciles.** For every template the scaffold ships, a verdict against
  the project's manifest: update and re-record, install, or keep and name the
  reason — edited, unknown, deleted. The playbook template changed in 3.11.0, so
  the update path fired on a real tree for the first time. Prettier runs on what
  was written before it is recorded.
- **Its verify phase is designed to go red.** The refreshed lint may find what
  the old one hid; story-loom's real `templates.md` is the case. The refresh
  stays, the run stops before the version markers, the message says how many
  problems are new against a baseline taken under the old CLI, and a re-run
  passes once they are worked.
- **Its preflight names the owning migration** for a tree that is behind, rather
  than calling it not a project-docs tree.

## What the skill learned from a second author

Seven gaps, each found by building and fixed in place: a post-copy marker check
the skill required but phase 2 had made unreachable; the rule that the scaffold
phase verifies every marker a later phase needs, in both modes, before writing;
no description of a reconciling phase; no notion of a verify phase meant to go
red, nor of a baseline; the invariant wording "every recorded hash" being wrong
for a reconciling run; preflight naming the owning migration; and the flags list
and related resources. The first author found five; the second found seven. The
skill is converging, not converged.
