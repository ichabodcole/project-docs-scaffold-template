## Constraints

- **Ordering is load-bearing.** Phase 1 (the skill rewrite) lands before phase 3
  (the script) is authored, because the script is the test of the skill. Every
  round-trip from phase 3 back to phase 1 is recorded.
- **This repository cannot dogfood the result.** Its markers are at the current
  release with a seed manifest. Validation is the two generated fixtures and the
  MediaForge run, never "apply it to our own docs".
- **The codemod stays self-contained** — no import from the tree it migrates —
  and its table-pinning test keeps passing unchanged.
- **Every guard is watched failing** before it is trusted, and the observation
  is written down under a `Guards watched failing` heading in the session note.
  A green `bun test` does not satisfy this.
- **Hand off to the v2.9 script; do not chain.** The v2.9 migration is the
  reference, not a target.
- **The script ends before the gate.** `lint.adopting: true`, `pdocs report`
  printed, exit 0. Backfill, catalog, and gate-on are named agent steps after
  it.
- **Two trees are playgrounds, not consumers:** `dreamwood/dream-flute` and
  `agent-cli-conformance`. Nothing on this branch targets them.
- **Version bump is minor** (`project-docs` 3.9.0 → 3.10.0). `dist/` is rebuilt
  and `npm run check` is the gate for every commit.
- **Orchestration model:** the main session is the editor. Subagents implement
  each phase and independent subagents review; the editor reads the result
  against the plan before anything is committed.
