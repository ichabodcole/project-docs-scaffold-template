# v2.9 → v2.10: refresh the owned files

A consumer on 8.0.0 has the layer but not the fixes from
[story-loom feedback, round 1](./2026-09-14-story-loom-feedback-round-1.md):
`scripts/pdocs/lint/rules.ts` and the codemod ship in the scaffold payload and
reach a project only through a migration. Story-loom holds `templates.md`
correct by hand until this lands.

## What it does

Script-shaped, authored under `migration-authoring`: preflight, scaffold,
refresh the **owned** files (`scripts/pdocs/`, `docs/SCHEMA.md`), reconcile the
**seeded** templates through `seed.ts` — the first migration to use the API v2.9
shipped, so the update/keep-modified/keep-unknown paths get their first real run
— verify, version markers, cleanup. Its precondition is a content test on the
installed CLI — `rules.ts` lacking `isSeeded` — rather than a version number: a
working tree's markers carry the last tag's number, so a version test cannot
tell a tree that is behind from one that is current.

## Why it matters beyond the fixes

It is the first migration written under the rewritten skill by someone other
than the skill's own test author, and the first to exercise seeded-template
reconciliation on a real tree. Both are things the migration-shape project could
not check.
